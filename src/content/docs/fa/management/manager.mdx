`row-template` را بدون آرگومان، با root و در ترمینال اجرا کنید:

```bash
row-template
```

```text
  Row-Template / by iitzSeriZdev
  ------------------------------------------------------------
  Version         1.2.0
  3X-UI           3.7.0
  Status          Installed / Active
  Template        Row
  Theme           Row-Template (active)
  Service         x-ui (running)

  1  Update
  2  Reconfigure branding
  3  Verify installation
  4  Rollback
  5  Activate / Re-apply theme
  6  Installation info
  7  Uninstall
  0  Exit
  Select [0-7]:
```

هر گزینه همان کد آزموده‌شدهٔ فرمان متناظرش را اجرا می‌کند. کاری که شکست بخورد، به‌جای بستن منو شما را به آن برمی‌گرداند.

## داشبورد

وضعیت بر اساس شواهد تعیین می‌شود — فایل‌های روی دیسک و مقدار واقعی `subThemeDir` پنل — و هرگز فقط از روی وجود فایل‌ها.

| وضعیت | معنی |
|---|---|
| **Installed / Active** | نصب شده و `subThemeDir` پنل به Row-Template اشاره می‌کند. |
| **Installed / Not active** | نصب شده، اما پنل پوشهٔ پوستهٔ دیگری را ارائه می‌کند یا هیچ پوشه‌ای ندارد. از گزینهٔ **5** استفاده کنید. |
| **Installed / Activation unverified** | نصب شده؛ تنظیم پنل اینجا خوانده نمی‌شود (`sqlite3` نیست یا پایگاه‌داده پیدا نشد). |
| **Installation damaged** | فایل‌هایی وجود ندارند یا صفحهٔ زنده در اعتبارسنجی رد می‌شود. گزینهٔ **3 — Verify** را اجرا کنید و سپس با اجرای دوبارهٔ نصب‌کننده تعمیر کنید. |

**Service** نشان می‌دهد سرویس `x-ui` در حال اجراست یا نه، یا `not detected`.

## گزینه‌ها

| گزینه | کار |
|---|---|
| **1 — Update** | آخرین نسخه را از منبع نسخه بررسی و با نسخهٔ شما مقایسه می‌کند. اگر جدیدتر باشد می‌پرسد `Update <current> -> <latest> now?`. اگر به‌روز باشید، پیشنهاد نصب دوباره می‌دهد. اگر این نصب از 1.1.0 آمده و اجزای نصب‌کننده را ندارد، پیشنهاد نصب دوباره برای کامل کردن آن را می‌دهد. اگر به منبع دسترسی نباشد، این را اعلام می‌کند و چیزی را تغییر نمی‌دهد. |
| **2 — Reconfigure branding** | زیرمنوی پایین را باز می‌کند. |
| **3 — Verify installation** | [`row-template verify`](/docs/management/verify/) را اجرا می‌کند. |
| **4 — Rollback** | جدیدترین پشتیبان معتبر را برمی‌گرداند، مثل `row-template rollback`. برای انتخاب پشتیبانی مشخص، از `row-template rollback --to` در پوسته استفاده کنید. |
| **5 — Activate / Re-apply theme** | پوشهٔ پوستهٔ فعلی پنل را نشان می‌دهد، پیشنهاد اتصال آن به Row-Template را می‌دهد و سپس بررسی‌های زنده را اجرا می‌کند. بدون تأیید شما چیزی نوشته نمی‌شود. [فعال‌سازی ←](/docs/installation/activation/) |
| **6 — Installation info** | نسخه، توسعه‌دهنده، GitHub، نسخهٔ 3X-UI، پوشهٔ نصب، تمپلیت، وضعیت پوسته، سرویس، و اینکه لوگوی سفارشی و لینک پشتیبانی تنظیم شده‌اند یا نه. هرگز لینک‌های اشتراک، شناسه‌ها، اطلاعات ورود یا خود لینک پشتیبانی را نشان نمی‌دهد. |
| **7 — Uninstall** | [`row-template uninstall`](/docs/management/uninstall/) را اجرا می‌کند که اول تأیید می‌گیرد. |
| **0 — Exit** | خروج از منو. |

## Reconfigure branding

```text
  1  Service name
  2  Support URL
  3  Logo
  4  Template
  5  Reset branding
  6  Reconfigure everything
  0  Back
```

هر مورد یک چیز را تغییر می‌دهد و صفحه را به‌صورت امن دوباره می‌سازد — [برندینگ](/docs/configuration/branding/) و [تعویض تمپلیت](/docs/templates/choosing/) را ببینید.

## منو یا فرمان‌ها؟

هر دو یک پیاده‌سازی مشترک دارند، با یک تفاوت که دانستنش مهم است:

- **Update** در منو اول نسخه‌ها را مقایسه می‌کند و پیش از هر کاری می‌پرسد.
- `row-template update` در خط فرمان **همیشه** آخرین نسخهٔ پایدار را دانلود و اعمال می‌کند، حتی اگر همان نسخه‌ای باشد که از قبل دارید. به همین دلیل راهی مطمئن برای تعمیر یا کامل کردن نصب است.

ورودی نامعتبر فقط دوباره پرسیده می‌شود (`Invalid option. Choose a number 0-7.`). وقتی ترمینالی برای خواندن وجود ندارد، منو پایان ورودی را **0 — Exit** در نظر می‌گیرد، پس هرگز اسکریپتی را معطل نمی‌کند.
