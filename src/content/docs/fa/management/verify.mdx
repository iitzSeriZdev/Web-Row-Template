```bash
row-template verify
```

پس از نصب، پس از هر تغییر و پیش از گزارش مشکل اجرایش کنید. با root اجرایش کنید: با کاربر دیگر نمی‌تواند `config.env` یا تنظیمات پنل را بخواند.

`verify` هرگز صفحه، برندینگ یا پنل شما را تغییر نمی‌دهد. با root، اول یک کار انجام می‌دهد: **مخزن تمپلیت‌ها** را مرتب می‌کند — طرح‌هایی که به‌روزرسانی قبلی بیرون از `dist/templates/` جا گذاشته به داخل برگردانده می‌شوند، و طرح‌هایی که نسخهٔ نصب‌شده دارد اما روی سرور نیستند از همان نسخه (با بررسی چک‌سام) دانلود می‌شوند. هیچ چیز دیگری را تغییر نمی‌دهد.

## خواندن نتیجه

هر بررسی یک خط چاپ می‌کند:

- `ok` — بررسی موفق بود.
- `warn` — ارزش اصلاح دارد، اما صفحه کار می‌کند. هشدارها هرگز فرمان را ناموفق نمی‌کنند.
- `FAIL` — مشکل جدی. فرمان با `verification FAILED (…)` تمام می‌شود و با کد `1` خارج می‌شود.
- خطی بدون برچسب، اطلاعات است؛ مثلاً بررسی‌ای که اینجا قابل اجرا نبود.

خط آخر جمع‌بندی است:

```text
  ok   verification passed with no warnings.
  warn verification passed with 2 warning(s).
  FAIL verification FAILED (1 hard issue(s), 2 warning(s)).
```

## همهٔ بررسی‌ها

### فایل‌ها و یکپارچگی

| نتیجه | خط | چه باید کرد |
|---|---|---|
| ok | `Install root present: …` | — |
| FAIL | `install root missing or is a symlink: …` | نصب‌کننده را دوباره اجرا کنید. پوشهٔ نصب باید یک پوشهٔ واقعی باشد. |
| ok | `Canonical artifact integrity verified.` | — |
| FAIL | `canonical artifact missing checksum or does not match it.` | طرح نصب‌شده تغییر کرده یا خراب شده. برای نصب دوباره `row-template update` را اجرا کنید. |
| FAIL | `canonical artifact missing or unreadable: …` | `row-template update` را اجرا کنید، یا نصب‌کننده را دوباره اجرا کنید. |
| ok | `Live template is structurally valid and readable.` | — |
| FAIL | `live template failed structural validation.` / `live template missing or unreadable: …` | آن را دوباره بسازید: `row-template update`، یا برای تعمیر نصب‌کننده را دوباره اجرا کنید. |
| ok | `VERSION present: …` | — |
| FAIL | `VERSION file missing or empty.` | برای تعمیر، نصب‌کننده را دوباره اجرا کنید. |

### بررسی‌های زنده

`verify` یک اشتراک را دو بار به‌صورت محلی درخواست می‌کند — یک بار مانند مرورگر و یک بار مانند اپ VPN. در 3X-UI اشتراکی برای آزمایش را از طریق `sqlite3` پیدا می‌کند؛ در PasarGuard و Rebecca که Row-Template هرگز خودش دنبال لینک اشتراک نمی‌گردد، این بررسی‌ها فقط وقتی اجرا می‌شوند که لینکی را در `RT_SMOKE_URL` بدهید:

```bash
RT_SMOKE_URL='https://your-panel.example.com/sub/…' row-template verify
```

| نتیجه | خط | چه باید کرد |
|---|---|---|
| ok | `Live render check: a browser receives Row-Template.` | — |
| warn | `live render check: the panel served its built-in page.` | پنل هنوز Row-Template را ارائه نمی‌کند — فعال‌سازی را بررسی کنید و پنل را ری‌استارت کنید. |
| warn | `live render check: the subscription endpoint was unreachable.` | پورت اشتراک به‌صورت محلی پاسخ نداد. بررسی کنید پنل در حال اجرا و سرویس اشتراکش فعال باشد. |
| — | `Live render check skipped (no test URL available).` | کاری لازم نیست. |
| ok | `VPN-client check: normal subscription content is served.` | — |
| warn | `VPN-client check: HTML was returned instead of subscription content.` | اپ‌های VPN به‌جای پیکربندی، صفحه را دریافت می‌کردند. بررسی کنید پراکسی یا CDN جلوی پنل درخواست را بازنویسی نکند. |

لینک اشتراکی را که برای `RT_SMOKE_URL` به کار می‌برید هرگز در گزارش خطا نگذارید.

## فایل‌های موقت باقی‌مانده

هر فایلی که Row-Template جایگزین می‌کند اول با نامی موقت که با `.stage.` یا `.live.` شروع می‌شود نوشته و سپس جایگزین می‌شود. اگر فرمانی نیمه‌کاره رها شود — برق سرور برود یا پردازه کشته شود — ممکن است یکی از آن‌ها باقی بماند. این فایل‌ها هرگز استفاده نمی‌شوند. وقتی هیچ فرمان `row-template` در حال اجرا نیست، حذفشان بی‌خطر است (در PasarGuard و Rebecca از `/etc/row-template` استفاده کنید):

```bash
find /etc/3x-ui/sub_templates/row-template -maxdepth 2 \( -name '.stage.*' -o -name '.live.*' \) -print -delete
```

سپس `row-template verify` را دوباره اجرا کنید.
