```bash
row-template update
```

این فرمان **آخرین نسخهٔ پایدار** را دانلود، بررسی و اعمال می‌کند. برندینگ و طرح انتخابی شما حفظ می‌شوند.

<Callout type="info" title="این فرمان همیشه آخرین نسخه را اعمال می‌کند">
  `row-template update` نسخه‌ها را مقایسه نمی‌کند: آخرین نسخه را حتی اگر همان را داشته باشید دوباره اعمال می‌کند، و همین آن را به راهی مطمئن برای تعمیر تبدیل می‌کند. گزینهٔ **1 — Update** در منوی مدیریت است که اول بررسی می‌کند و می‌پرسد — [منوی تعاملی مدیریت](/docs/management/manager/) را ببینید.
</Callout>

## چه اتفاقی می‌افتد

<Steps>

### دانلود و بررسی

نسخه از GitHub (یا از `RT_RELEASE_DIR` / `RT_RELEASE_URL`) دریافت می‌شود، SHA-256 آن بررسی می‌شود و آرشیو بررسی و استخراج می‌شود — دقیقاً مثل نصب تازه.

### بررسی نسخهٔ جدید

صفحهٔ جدید اعتبارسنجی می‌شود، همهٔ فایل‌های نصب‌کننده‌ای که نسخه اعلام کرده باید وجود داشته باشند و با چک‌سامشان بخوانند، و همهٔ طرح‌های نسخه پس از بررسی به مخزن تمپلیت‌ها وارد می‌شوند. هر مشکلی به‌روزرسانی را همین‌جا، **پیش از هر تغییری**، متوقف می‌کند.

### حفظ طرح شما

طرح فعلی شما از نسخهٔ جدید برداشته می‌شود. اگر نسخهٔ جدید آن را نداشته باشد، از Row استفاده می‌شود و به شما هشدار داده می‌شود.

### پشتیبان‌گیری

از نصب فعلی پشتیبان گرفته می‌شود. اگر ممکن نباشد، به‌روزرسانی متوقف می‌شود.

### آماده‌سازی و فعال‌سازی

صفحهٔ جدید، `VERSION`، کتابخانهٔ مدیریتی، اجزای آن و فرمان `row-template` نصب می‌شوند؛ سپس صفحهٔ زنده از روی نسخهٔ جدید و با برندینگ شما دوباره ساخته، اعتبارسنجی و جایگزین می‌شود.

</Steps>

به‌روزرسانی موفق این را چاپ می‌کند:

```text
  Updating Row-Template 1.1.0 -> 1.2.0
  ok   Update complete: now running 1.2.0.
```

و پس از آن بررسی‌های زنده را. سپس پشتیبان‌های قدیمی تا دو پشتیبان جدیدتر حذف می‌شوند.

## اگر فعال‌سازی شکست بخورد

نسخهٔ قبلی به‌صورت خودکار از پشتیبان بازگردانده می‌شود:

```text
  FAIL activation of the new version failed; rolling back.
  warn rolled back to 1.1.0; no changes are live.
```

فرمان با کد `1` خارج می‌شود. مشترکان در تمام این مدت صفحهٔ قبلی را می‌بینند. اگر بازگردانی خودکار هم شکست بخورد — که به دو شکست مستقل نیاز دارد — به شما گفته می‌شود `row-template rollback` را اجرا کنید.

## ارتقا از 1.1.0

به‌روزرسانی از 1.1.0 به **دو بار اجرای** `row-template update` نیاز دارد:

<Steps>

### اجرای اول — توسط به‌روزرسان 1.1.0

```bash
row-template update
```

فرمانی که اجرا می‌کنید هنوز فرمان 1.1.0 است. نسخهٔ 1.2.0 را نصب می‌کند: صفحه به‌روز می‌شود و برندینگ حفظ می‌شود. اما به‌روزرسان 1.1.0 فقط کتابخانه و فرمان را کپی می‌کند، پس مخزن تمپلیت‌ها و اجزای جدید نصب‌کننده هنوز نصب نشده‌اند و فقط Row در دسترس است.

### بررسی

```bash
row-template verify
```

به شما می‌گوید اجرای دوم لازم است:

```text
  FAIL template store missing or empty; run 'row-template update' to install it.
  warn installer components are missing (lib/transaction.sh, panels/), as after an update from 1.1.0; run 'row-template update' to complete the installation.
```

### اجرای دوم — توسط 1.2.0

```bash
row-template update
```

حالا به‌روزرسان 1.2.0 اجرا می‌شود. همهٔ طرح‌ها و بقیهٔ فایل‌های نصب‌کننده را نصب می‌کند. پس از آن `row-template verify` موفق است و می‌توانید [طرح انتخاب کنید](/docs/templates/choosing/).

</Steps>

در منوی مدیریت، گزینهٔ **1 — Update** این وضعیت را تشخیص می‌دهد و می‌پرسد `Re-install 1.2.0 now to complete it?`.

## به‌روزرسانی بدون دسترسی به GitHub

به‌روزرسانی را به پوشه‌ای ارجاع دهید که نسخه‌ای را که خودتان دانلود و بررسی کرده‌اید در خود دارد:

```bash
RT_RELEASE_DIR=/root/row-template-X.Y.Z-release row-template update
```

[نصب دستی](/docs/installation/manual/) را ببینید.

## چیزهایی که به‌روزرسانی هرگز تغییر نمی‌دهد

- **برندینگ** شما (`config.env`).
- **طرح** شما، تا وقتی نسخهٔ جدید آن را داشته باشد.
- **تنظیمات پنل** — `subThemeDir` از قبل به پوشهٔ نصب اشاره می‌کند و این پوشه جابه‌جا نمی‌شود.
- **پشتیبان‌های** موجود، جز حذف موارد قدیمی تا دو پشتیبان معتبر جدیدتر.

برای برگشت به نسخه‌ای که پیش از به‌روزرسانی داشتید، از [بازگردانی](/docs/management/rollback/) استفاده کنید.
