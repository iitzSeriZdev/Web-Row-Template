Row-Template روی همان سروری اجرا می‌شود که پنل 3X-UI شما روی آن است. به چیزی جز ابزارهای استاندارد لینوکس نیاز ندارد؛ تنها افزودنی اختیاری، `sqlite3`، باعث می‌شود Row-Template خودش را فعال کند و لازم نباشد یک فیلد را در پنل تنظیم کنید.

## در یک نگاه

| پیش‌نیاز | برای | الزامی؟ |
|---|---|---|
| 3X-UI (MHSanaei) **نسخهٔ 3.6.0 یا جدیدتر** | همه چیز — نصب‌کننده نسخه‌های قدیمی‌تر یا غیرقابل تشخیص را رد می‌کند | بله |
| دسترسی root | نصب، پیکربندی، به‌روزرسانی، بازگردانی و حذف | بله |
| `bash`، `tar`، `sha256sum` (یا `shasum`) | بررسی و باز کردن نسخه | بله |
| `curl` | دانلود نسخه و بررسی‌های زندهٔ صفحه | بله، مگر اینکه [از پوشهٔ محلی نصب کنید](/docs/installation/manual/) |
| `sqlite3` | تنظیم خودکار `subThemeDir` پنل، بررسی آن در `verify` و بررسی‌های زندهٔ صفحه | اختیاری |
| `systemd` با سرویس `x-ui.service` | توقف و راه‌اندازی دوبارهٔ پنل هنگام نوشتن خودکار `subThemeDir` | اختیاری |
| دسترسی HTTPS به GitHub | نصب یک‌خطی و `row-template update` | مگر اینکه از پوشهٔ محلی نصب کنید |

**سیستم‌عامل پیشنهادی:** Ubuntu 24.04 LTS (x86_64). توزیع‌های جدید دیگر لینوکس هم احتمالاً کار می‌کنند، اما به همان اندازه آزموده نشده‌اند.

Row-Template هیچ محیط اجرایی‌ای به سرور اضافه نمی‌کند: نه Node.js، نه Python، نه پایگاه‌داده و نه سرویس پس‌زمینه.

## بررسی پنل

نصب‌کننده فایل اجرایی پنل را به ترتیب در `/usr/local/x-ui/x-ui`، سپس `/usr/local/bin/x-ui` و سپس هر `x-ui` موجود در `PATH` جست‌وجو می‌کند و به دنبال سرویس systemd با نام `x-ui.service` هم می‌گردد. نسخه را از خود فایل اجرایی می‌خواند:

```bash
/usr/local/x-ui/x-ui -v
```

اولین `X.Y.Z` در خروجی باید **3.6.0 یا جدیدتر** باشد. اگر نسخه اصلاً خوانده نشود، نصب‌کننده به‌جای حدس زدن متوقف می‌شود — [`cannot determine the 3x-ui version`](/docs/help/errors/#cannot-determine-the-3x-ui-version-refusing-to-proceed) را ببینید.

## بررسی ابزارها

```bash
for t in bash tar curl sha256sum sqlite3; do
  command -v "$t" >/dev/null && echo "ok      $t" || echo "missing $t"
done
```

ممکن است روی برخی سیستم‌ها `sha256sum` نباشد و به‌جای آن `shasum` باشد؛ نصب‌کننده هر دو را می‌پذیرد.

## نصب sqlite3 (اختیاری)

نصب‌کننده هرگز `sqlite3` را برایتان نصب نمی‌کند. اگر فعال‌سازی خودکار می‌خواهید، اول آن را نصب کنید:

بدون آن هم همه چیز کار می‌کند — فقط یک بار **Sub Theme Directory** را دستی در پنل تنظیم می‌کنید. [فعال‌سازی](/docs/installation/activation/) را ببینید.

## پایگاه‌دادهٔ پنل از کجا پیدا می‌شود

برای فعال‌سازی خودکار، Row-Template باید پایگاه‌دادهٔ پنل را هم پیدا کند. از **اولین** موردی که وجود داشته باشد استفاده می‌کند:

1. `$XUI_DB_FOLDER/x-ui.db`، وقتی متغیر محیطی `XUI_DB_FOLDER` تنظیم شده باشد
2. `/etc/x-ui/x-ui.db`
3. `/usr/local/x-ui/x-ui.db`
4. `/etc/3x-ui/x-ui.db`

اگر آن فایل پایگاه‌دادهٔ SQLite واقعی نباشد، با یک هشدار رد می‌شود و Row-Template **سراغ مسیر بعدی نمی‌رود** — فایل دیگر ممکن است متعلق به نصبی قدیمی یا نامرتبط باشد. در این حالت فعال‌سازی به روش دستی برمی‌گردد.

## شبکه

نصب یک‌خطی و `row-template update` فقط از طریق HTTPS از `https://github.com/iitzSeriZdev/Row-Template/releases/latest/download/` دانلود می‌کنند. سروری که به GitHub دسترسی ندارد را هم می‌توان از پوشه‌ای که به آن کپی می‌کنید نصب و به‌روزرسانی کرد: [نصب دستی](/docs/installation/manual/) را ببینید.
